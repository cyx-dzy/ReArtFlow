## 2. 页面结构重构：取消左侧常驻文件索引，增大图谱面积

当前左侧常驻文件索引 / 文件列表区域需要取消。

取消的是左侧常驻 UI，不是取消文件数据，也不是取消文件搜索能力。

必须保留：

- 后端仍返回所有被解析出来的主体源码文件；
- 图谱中仍展示所有被解析出来的主体源码文件节点；
- 用户仍可以搜索文件；
- 搜索结果能定位或高亮图谱中的文件节点；
- 点击文件节点后仍能查看源码；
- 源码预览标题中仍显示文件路径；
- 文件列表如有必要，只能作为弹窗、抽屉、命令面板或临时浮层出现，不得作为常驻左栏占用图谱空间。

页面布局要求：

- 顶部保留 Zip、本地目录、GitHub、Gitee 输入能力，但输入区和操作区要压缩高度。
- 中央主体区域最大化展示结构图谱。
- 图谱区域默认应占据页面主体的大部分面积。
- 桌面端图谱区域目标占主体内容宽度的 75% 到 90%。
- 源码预览默认不要长期压缩图谱主体，可以使用右侧可折叠抽屉、底部可折叠面板、浮层详情面板或可拖拽详情区。
- 用户点击图谱节点后，源码预览再明显展开或更新。
- 初始进入结果页时，用户第一眼看到的是完整、居中、可读的结构图谱。

## 3. 保留每一个被解析出来的主体源码文件

“被解析出来”指经过现有资源过滤后进入主体源码解析结果的文件。

不要把这些资源重新纳入主体代码图谱：

- 图片；
- PDF；
- CSV / Excel；
- 压缩包；
- 字体；
- 音视频；
- 其他非主体框架源码资源。

图谱中默认必须出现每一个已解析源码文件的文件节点。

请检查并修改 backend/diagram/project_graph.py、backend/diagram/converter.py 以及相关逻辑中可能导致文件节点丢失的限制，例如：

- MAX_FILES_PER_GROUP
- MAX_AI_NODES
- MAX_GRAPH_NODES
- 每组文件数量限制
- AI 输出节点数量限制
- 全局图谱节点数量限制
- 任何会让普通项目的已解析源码文件从图谱数据中消失的逻辑

要求：

- 普通项目默认不能隐藏已解析文件。
- 如果 AI 图谱遗漏某些真实文件，必须用静态兜底结果合并补全。
- 最终返回给前端的数据必须包含所有真实解析文件节点。
- 可以保留极大项目的安全上限防止浏览器崩溃，但如果启用折叠或分页，必须提供明确展开方式，并且文件搜索仍能检索所有文件。
- 无 API Key、AI 失败、关闭 AI 时，静态兜底仍然必须生成完整图谱。

## 4. 每个文件节点显示“文件名 + 一句简短中文描述”

每个文件节点必须包含并显示：

- 第一行：真实文件名，例如 App.vue、project_graph.py、package.json。
- 第二行：一句简短中文描述，建议 12 到 28 个中文字符。
- 完整相对路径 path。
- language。
- groupId 或 module。
- isFile 或 nodeKind 字段。

描述来源优先级：

1. AI 对文件职责的描述；
2. 静态解析出的函数、类、路由、组件、导入关系；
3. 根据路径、语言、文件名生成的确定性描述。

要求：

- 没有 API Key、AI 失败、关闭 AI 时，静态兜底也必须为每个文件生成 description。
- 不允许为了美观把文件名截断到无法识别。
- 节点视觉上可以省略过长路径，但文件名必须完整可见。
- tooltip 或节点详情中必须显示完整 path、language、description、groupId / module、文件大小或其他已有元信息。

## 5. 相同模块的文件放在一起

请根据目录和职责自动分组。

参考分组：

- 前端模块：frontend、src、components、views、router、store、vite 等。
- 后端模块：backend、api、routes、parser、diagram、semantic、input、security 等。
- 语义理解模块：semantic、prompt、llm、ai、model 等。
- 图谱生成模块：diagram、graph、converter、layout 等。
- 测试模块：tests、test、spec 等。
- 文档模块：docs、README、markdown 文档等。
- 配置与构建模块：package.json、vite.config.ts、tsconfig.json、pyproject、requirements、config、yaml 等。

要求：

- 后端图谱数据中补充或稳定 group / combo 信息。
- 前端使用 G6 combo、模块背景、分组容器或自定义分组视觉展示。
- 模块区域需要中文标题和简短说明，例如：
  - 前端交互层
  - 后端解析服务
  - 语义理解层
  - 图谱生成层
  - 测试与验证
  - 配置与构建
- 同一模块内的文件节点应尽量相邻排列，不要散落在画布各处。
- 跨模块关系可以连线，但要尽量避免破坏模块聚合感。

## 7. 文件之间用连线表达关系，边标签必须水平

保留并增强文件之间的关系边，例如：

- import / imports：导入
- calls / uses：调用或使用
- routes_to：路由到
- renders：渲染
- depends_on：依赖
- reads / writes：读取或写入
- contains：包含
- configures：配置
- tests：测试

要求：

- 边的中文标签必须保持水平显示。
- 不要让边标签随着边方向旋转。
- 检查 frontend/src/components/Diagram.vue 中的边 label 配置。
- 确保 autoRotate 为 false，或使用自定义 edge label，使 rotation 始终为 0。
- 边标签要有浅色背景、内边距和足够对比度。
- 边标签不能和线条混在一起。
- 低价值的 contains 边可以弱化样式，但仍需可理解。
- hover 节点时高亮相关边和邻居节点，弱化无关元素。

## 8. 尽量避免连线重叠、穿过节点和标签遮挡

当前前端使用 AntV G6。请使用与当前 @antv/g6 版本兼容的方案，不要随意升级大版本。

可以继续使用 dagre、compactBox 或自定义预处理布局，但必须实现：

- 模块分组感；
- 尽量少的边交叉；
- 尽量少的边重叠；
- 边不明显穿过节点主体；
- 标签不明显互相遮挡。

优先采用：

- 正交折线；
- 合理的 nodesep / ranksep；
- 同向边偏移；
- 平行边错位；
- 跨模块边分层；
- labelCfg 背景；
- 模块内边优先在模块内走线；
- 跨模块边从模块边界出入；
- 低优先级边变淡；
- hover 高亮相关边；
- 点击节点时聚焦相关子图；
- fitView 后初始视图保持可读。

验收时至少用：

1. 一个小型示例项目；
2. ReArtFlow 项目自身。

检查主要连线是否明显重叠、穿节点或遮挡标签。

## 15. 工作方式

请按以下顺序工作：

1. 阅读关键文件。
2. 使用 uiuxpromax 给出简短 UI/UX 方案。

- 已完成；
