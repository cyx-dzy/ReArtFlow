# Diagram UI Acceptance

## 核心改动文件

- `backend/diagram/project_graph.py`：生成精简 G6 图谱数据，按模块选取代表性文件节点、模块分组、文件描述和安全过滤后的关系边。
- `tests/backend/test_project_graph.py`：覆盖静态兜底完整性、AI 漏文件补齐、非法边过滤和旧文件数量限制移除。
- `frontend/src/components/Diagram.vue`：渲染 GitDiagram 式紧凑模块图谱，使用白底模块框、文件卡片、数据库圆柱卡片和水平边标签。
- `frontend/src/App.vue`：重构为明亮图谱工作台，取消左侧常驻文件索引，提供文件搜索浮层和源码预览抽屉。
- `frontend/package.json` / `frontend/package-lock.json`：加入 `highlight.js` 作为源码高亮依赖。

## uiuxpromax 设计摘要

产品类型是面向非技术人员的代码结构理解工具。界面采用明亮、清爽、低装饰的专业工作台风格：顶部是压缩输入控制条，主体把结构图谱作为视觉中心，交互控件保持 44px 以上触达面积、清晰焦点态和中文文案。图谱本身使用白底模块容器、轻网格画布、柔和阴影和功能色来区分文件职责，避免大面积深色后台风格。

## 页面布局调整

顶部保留 Zip、本地路径、GitHub、Gitee 四种输入方式，并把输入区压缩成一条工作台控制台。主体区域只有结构图谱常驻显示，图谱画布在桌面端默认占据主体宽度的绝大部分。解析进度、Project ID 和错误提示位于顶部控制台下方，不遮挡图谱。

## 取消左侧文件索引后的替代交互

左侧常驻文件列表已取消。文件搜索通过“搜索文件”按钮打开居中的命令面板式浮层，用户可以按文件名、路径或语言搜索所有项目文件。选择搜索结果后会关闭浮层、高亮对应图谱节点，并打开右侧源码预览抽屉。

## 图谱面积增大方式

`App.vue` 的主体布局从三栏常驻布局改为单一图谱舞台。源码预览不再常驻占位，而是绝对定位的右侧抽屉；未打开时不会压缩图谱。`Diagram.vue` 的画布高度使用 `72vh` 和 `640px` 最小高度，初始视图通过 G6 `fitView` 居中显示。

## 后端图谱数据完整性

`project_graph.py` 现在区分“完整文件数据”和“默认图谱展示数据”：文件浏览 API 仍返回所有主体源码文件，默认结构图谱则按模块选取代表性文件节点，避免大项目图谱过密。默认上限为 28 个文件节点、每组最多 5 个文件、64 条边，可通过 `DIAGRAM_MAX_FILE_NODES`、`DIAGRAM_MAX_FILES_PER_GROUP`、`DIAGRAM_MAX_EDGES`、`DIAGRAM_MAX_AI_FILE_NODES`、`DIAGRAM_MAX_AI_EDGES` 调整。展示节点保留 `id`、`label`、`filename`、`path`、`language`、`description`、`groupId`、`module`、`type`、`shape`、`color`、`nodeKind` 和 `size` 等字段。

资源过滤仍由 parser 和 project file 逻辑负责，图片、PDF、CSV/Excel、字体、音视频、压缩包、构建产物和依赖目录不会进入主体源码图谱。

## 文件节点 description 策略

文件描述优先使用 AI 单文件解释；没有 AI 解释时，使用静态 AST 摘要生成中文描述，例如函数、类、导入和调用数量；如果文件没有明显 AST 信号，则根据路径、语言和职责分类生成确定性中文描述。这样无 API Key、AI 失败或关闭 AI 时，每个文件节点仍有非空描述。

## AI 图谱与静态兜底合并策略

AI 图谱会先经过安全归一化：节点路径必须来自真实解析文件，非法路径节点会被丢弃；边的 source / target 必须引用已存在节点，非法边会被过滤。归一化后再从静态兜底图谱补齐代表性文件节点，并补齐对应模块组和模块关系，保证默认 G6 数据精简可读，同时完整文件仍可通过文件搜索和源码 API 访问。

## 边标签水平显示

`Diagram.vue` 中默认边和每条边的 `labelCfg.autoRotate` 都设置为 `false`。边标签使用白色背景、浅蓝边框、内边距和深色文本，避免文字跟随折线旋转，也避免标签和线条混在一起。

## 连线避让与布局策略

图谱使用 G6 预设网格定位、正交折线和 combo 分组。模块容器只作为白底背景框，不作为普通节点绘制，也不允许拖动；文件节点拖拽可由页面上的“节点拖拽”开关控制。默认关闭节点拖拽以保持布局稳定。跨模块关系优先用模块间边表达，文件级边数量受上限控制，模块内孤立文件会补充轻量“关联”边，hover 时高亮相关边和邻居节点以降低重叠感。

## Atom One Dark 源码预览

源码预览使用 `highlight.js/lib/common` 和 `highlight.js/styles/atom-one-dark.css`。抽屉背景为 Atom One Dark 接近色 `#282c34`，并补充 VS Code 风格行号 gutter、hover 行背景和 token 颜色覆盖。高亮输出通过 highlight.js 生成后再用于 `v-html`；异常兜底会对原始文本执行 HTML 转义，避免直接拼接未转义源码。代码区支持横向和纵向滚动，标题显示完整文件路径，语言和截断状态以标签展示，点击源码抽屉侧边按钮可弹出完整源码预览。

## 手动验收方式

Zip：
1. 选择 Zip 输入。
2. 上传包含多语言源码的小项目。
3. 点击“生成图谱”，等待进度完成。
4. 检查每个解析源码文件都出现在图谱中，并可点击打开源码抽屉。

本地目录：
1. 选择“本地路径”。
2. 输入后端可访问的项目目录，例如 `D:\project\ReActFlow`。
3. 生成图谱后检查模块分组、文件搜索、源码预览和边标签。

GitHub / Gitee：
1. 选择对应输入方式。
2. 输入公开仓库地址。
3. 生成图谱后检查文件节点、模块分组、搜索浮层和源码抽屉。

无 API Key：
1. 清空对应 provider 的 API Key，或设置 `LLM_ARCHITECTURE_ENABLED=0`。
2. 重新解析项目。
3. 确认仍生成静态兜底图谱，文件节点和描述不为空。

## 已知限制

- AntV G6 仍由浏览器端布局，大型仓库可能出现较慢的初次布局；当前实现优先保证默认图谱精简，完整文件访问通过搜索和源码 API 保留。
- 关系边中的深层语义仍依赖 AI 图谱质量；无 API Key 时会使用静态启发式关系兜底。
- Vite 构建输出的主 chunk 超过 500 kB，后续可以通过按需拆分 G6/highlight.js 或路由级懒加载继续优化。
